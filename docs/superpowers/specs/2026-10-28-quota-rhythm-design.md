# 额度使用节奏定制设计

## 目标与范围

在作者现有 SwiftUI 界面中增加本月、本周的额度节奏信息，让使用者能判断当天最高可用到多少，并直观看到重置日期。以最终草图为准，不重做面板，不删除本机消耗量、操作按钮或版本区。

## 已确认方案

- 主额度卡顺序为本月、本周、5小时；月度和周度重置同时显示 `MM-dd HH:mm` 与原相对倒计时，5小时保持原样式。
- 在账号额度区与本机消耗量之间插入「本周使用节奏」，展示主 Kimi 账号的周重置周期。周开始为 `resetTime - 7天`，从开始日到重置日共8个日期节点；月度按项目已有的30天周期语义，以 `resetTime - 30天` 推算。
- 经典模式为4列×2行的低饱和8色卡片，同时展示周、月累计上限；今天只用轻阴影标示。极简模式一行8天，统一图例，只保留日期和周、月数值。底部一行展示日均周、月上限。
- 日节点按本地日历逐日生成，累计上限按节点占整个周期的比例计算；菜单栏的「今日周累计上限」按当前时刻在7天周期中的精确进度计算，并限制在0%到100%。
- 菜单栏只在周用量后追加小号、较弱的不透明度 `≤今日上限`，月度与5小时不变。默认双行、K前缀和单行样式同步适配，设置页实时预览使用同一计算。
- 刷新成功时间显示在刷新按钮内部第二行，格式 `MM/dd HH:mm`；四个按钮仍等高一排。只在主账号配额实际刷新成功后更新时间，失败时保留上次成功时间。
- 周节奏需要周额度及重置时间；月度数据或重置时间缺失时该列显示 `--`，无周数据时整个节奏区不占位。
- 浅色、深色、跟随系统以及中英文均沿用项目动态颜色和本地化机制。

## 方案取舍

采用独立 `QuotaRhythm.swift` 承载纯计算与周节奏视图，并只修改现有主文件中的接入点。相比把全部逻辑继续堆入主文件，这更利于后续维护；相比引入通用配置系统或新依赖，它符合作者直接、轻量的代码风格，也避免扩大功能范围。

## 验证与交付

项目没有自动化测试体系，不新增测试脚手架。通过 `xcodebuild build` 验证 Debug 编译，检查全部菜单栏调用点、字符串目录 JSON 和最终差异；按项目约定提交并推送，但不改版本号、不打标签、不启动 App。
